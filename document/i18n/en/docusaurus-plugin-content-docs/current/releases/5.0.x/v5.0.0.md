# v5.0.0 (Upcoming)

```xml
<dependency>
    <groupId>net.hasor</groupId>
    <artifactId>dataway-embedded</artifactId>
    <version>5.0.0</version>
</dependency>
```

## Changes

- Added
  - Separate DataQL engine, SQL executor, console resources, and Spring, Solon, and Hasor integration modules.
  - `DatawayConfig` assembles storage, identities, the engine, and Web entry points. `AdminService` manages APIs; `ApiService` invokes published, enabled APIs by path or ID.
  - JDBC and Nacos metadata modules support table and field mappings, optimistic version checks, and release history, with schema scripts for MySQL, PostgreSQL, Oracle, SQL Server, and H2.
  - `IdentityProvider` supplies application identities. Management and API interceptors expose operation permissions, target APIs, versions, and call origins in their respective contexts.
  - JSON, forms, file uploads, and Header/Cookie access, with configurable upload memory thresholds and temporary directories and cleanup after requests.
  - A binary data model and extensible result handlers: Structure, Raw Value, CSV, Text, and Verify Code. The console previews JSON, text, tables, and images and supports file downloads.
  - OpenAPI 3.0 and Swagger 2.0 endpoints, with independently configurable console, management API, business API, and documentation paths.
  - SQL connection, execution interception, and transaction extensions. Ordinary SQL and transaction functions can participate in Spring, Solon, or dbVisitor host transactions.
  - CASE/WHEN/ELSE and PAIRS dynamic SQL rules, Hive pagination and additional database dialect support, list-to-JDBC-array binding, binary reads and writes, and JSON/vector type handling.
- Fixed
  - Operator precedence and short-circuit evaluation now follow Java/JavaScript conventions; fixes cover negative numbers, scientific notation, string escaping, fragment arguments, and exits from nested functions.
  - Hint propagation, query cloning, Lambda scope restoration, collection indexing, string/collection functions, and HMAC algorithm selection.
  - Character, enum, and numeric-to-boolean conversions, missing object fields, and numeric width and SQL Hint defaults.
  - Nested dynamic SQL parsing, XML trim handling, pagination metadata synchronization, and repeated queries. Parameter marker escaping supports native commands used with [dbVisitor drivers](https://www.dbvisitor.net/docs/drivers/about).
  - CHAR/NCHAR truncation and driver result type detection; time zone results retain their offsets. Configuration values are checked for explicit null before JSON serialization.
- Improved
  - Queries are built through `HostConfiguration → QueryManager → QueryBuilder`, with unified Finder, host attachment, UDF, and fragment extensions, standalone execution, and JSR-223 integration.
  - Type handlers follow the DataQL data model. `TypeHandler` no longer uses generics or annotation mappings; explicit registration and parameter-level configuration remain available. JSON conversion uses Jackson throughout, and Cobble is upgraded to `5.0.4`.
  - The upgraded console is packaged separately, with Mock/proxy development and separate deployment. Maven examples cover all three frameworks, Nacos, and data transformations.
  - Reorganized Chinese and English manuals, migration guidance, SQL references, and `llms.txt`, with additional engine, storage, real HTTP, and executable documentation tests.

## Upgrade notes

- Module coordinates, configuration keys, and extension contracts have changed. See [framework integrations](../../dataway/integration/buildtools.md) and [core configuration](../../dataway/configuration/core.md) for `DatawayConfig` and default entry points.
- UDF calls now receive `UdfParams`; query options use `setHint(String, Object)`. Use `AdminService` for programmatic management and `ApiService` to invoke published APIs.
- Custom `TypeHandler` implementations use `Object` arguments and return values; `AbstractTypeHandler<T>` retains its type parameter. Use `TypeHandlerRegistry.register(...)` instead of mapping annotations or the `javaType` parameter option. See [SQL type handlers](../../dataway/engine/sql-types.md).
- Preserve original scripts, API IDs, and release history when migrating metadata; field mappings can reuse existing storage structures. Identity, interceptor, and extension changes are covered in the [migration guide](/blog/dataway-migration).
